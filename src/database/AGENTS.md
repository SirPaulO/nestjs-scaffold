# database/ — Database Layer

TypeORM entities, migrations, seeds, and the snake_case naming strategy.
Import via `@database/*` path alias.

---

## Structure

```
database/
├── entities/
│   └── base.entity.ts    # Abstract base: id (UUID), createdAt, updatedAt, deletedAt
├── migrations/           # Generated by TypeORM CLI — never edit by hand
├── seeds/                # Optional seed scripts (create seed.ts here for db:seed)
└── strategies/
    └── snake-naming.strategy.ts  # Converts all DB identifiers to snake_case
```

---

## Base Entity

All entities should extend `BaseEntity`:
```typescript
import { Entity, Column } from 'typeorm';
import { BaseEntity } from '@database/entities/base.entity';

@Entity()
export class User extends BaseEntity {
  @Column({ unique: true })
  email!: string;
}
```

This provides: `id` (UUID PK), `createdAt`, `updatedAt`, `deletedAt` (soft-delete).

---

## Migrations

```bash
npm run migration:generate -- src/database/migrations/AddUserTable
npm run migration:run
npm run migration:revert
```

- Never use `synchronize: true` in production.
- `DATABASE_SYNCHRONIZE=false` in `.env`.

---

## Naming Convention

The `SnakeNamingStrategy` converts all entity/column names to `snake_case` automatically.
FK names: `FK_{table}_{col}`, indexes: `IDX_{table}_{col}`, unique constraints:
`UQ_{table}_{cols}`, PKs: `PK_{table}`.
